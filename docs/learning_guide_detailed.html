1.1 先看 main.py —— 整个程序的最小入口

打开项目根目录下的 main.py 文件，它只有 17 行代码，但它是理解整个项目的钥匙。我们逐行解释：

Python main.py
1from tradingagents.default_config import DEFAULT_CONFIG 2from tradingagents.graph.trading_graph import TradingAgentsGraph 3 4# DEFAULT_CONFIG 已经包含了 TRADINGAGENTS_* 环境变量的覆盖 5# 所以用户可以通过 .env 文件切换模型，不需要改代码 6config = DEFAULT_CONFIG.copy() 7 8# 用自定义配置初始化 9ta = TradingAgentsGraph(debug=True, config=config) 10 11# 正向传播（执行分析） 12_, decision = ta.propagate("NVDA", "2026-09-01") 13print(decision)
逐行解释

第 1 行：从 tradingagents 包中导入 DEFAULT_CONFIG。这是一个 Python 字典（你可以理解为"配置表"），里面存了所有默认设置，比如用哪个 AI 模型、辩论几轮、数据从哪来等。

第 2 行：导入 TradingAgentsGraph 类。这是整个项目的"总指挥"，负责协调所有 AI 智能体一起工作。

第 6 行：DEFAULT_CONFIG.copy() 把默认配置复制一份。用 .copy() 是为了不修改原始配置（就像复印一份文件再在上面写字，原件不动）。

第 9 行：创建 TradingAgentsGraph 对象。debug=True 表示开启调试模式，会在控制台打印每一步的详细信息。config=config 把刚才的配置传进去。

第 12 行：ta.propagate("NVDA", "2026-09-01") 是核心调用！意思是"请分析 NVDA（英伟达）这只股票，分析日期是 2026-09-01"。返回两个值：_（完整状态，我们暂时不要）和 decision（最终决策，比如 "Buy" 或 "Sell"）。

第 13 行：打印最终决策结果。

什么是 propagate()？

propagate() 是 TradingAgentsGraph 类的一个方法，意思是"向前传播/执行"。你可以把它理解为"启动整个分析流水线"。

它接收 3 个参数：

  • company_name（必填）：股票代码，如 "NVDA"、"AAPL"、"0700.HK"（港股腾讯）
  • trade_date（必填）：分析日期，格式 "YYYY-MM-DD"，不能是未来的日期
  • asset_type（可选）：资产类型，默认 "stock"（股票），加密货币用 "crypto"

它返回一个元组 (final_state, signal)：

  • final_state：包含所有分析师报告、辩论记录、最终决策的完整字典
  • signal：5 级评级之一 —— Buy / Overweight / Hold / Underweight / Sell，或 REVIEW（无法解析）

2.1 深入理解 default_config.py —— 所有配置的"总表"

这个文件定义了项目的所有默认配置。我们挑最重要的几个字段解释：

Python default_config.py（关键片段）
1def build_default_config() -> dict: 2 return _apply_env_overrides({ 3 "llm_provider": "openai", # 用哪个 AI 公司 4 "deep_think_llm": "gpt-6-sol", # 深度思考模型（经理层用） 5 "quick_think_llm": "gpt-6-luna", # 快速思考模型（分析师用） 6 "max_debate_rounds": 1, # 多空辩论几轮 7 "max_risk_discuss_rounds": 1, # 风控辩论几轮 8 "output_language": "English", # 报告语言 9 "holding_period_days": 5, # 持有几天后结算 10 "data_vendors": { 11 "core_stock_apis": "akshare,yfinance", # 行情（AKShare 优先，A 股友好） 12 "technical_indicators": "akshare,yfinance", # 技术指标 13 "fundamental_data": "sec_edgar,akshare,yfinance", # 财报（SEC 按 filed date） 14 "news_data": "akshare,yfinance", # 新闻数据源 15 "macro_data": "fred", # 宏观经济 16 "prediction_markets": "polymarket", # 事件定价；可换 sse_option / none 17 }, 18 # 工具级配置优先于类别级：全局新闻钉在 Yahoo， 19 # 免得美股分析读到上证快讯（A 股批量分析会把它改回 akshare） 20 "tool_vendors": {"get_global_news": "yfinance"}, 21 })
重点解释

双 Tier 模型：quick_think_llm 服务 4 个分析师 + 多空研究员 + 交易员 + 风控三方（共 10 个角色），deep_think_llm 服务经理层（2 个角色：研究经理 + 组合经理）。两个 tier 可以用不同的 AI 公司！比如 quick 用 OpenAI，deep 用 Anthropic。

data_vendors：每个数据类别可以配置一个或多个供应商，用逗号分隔就是 fallback 链。比如 "sec_edgar,akshare,yfinance" 表示先试 SEC EDGAR，失败再试 AKShare，最后 Yahoo Finance。预测市场类别可配 polymarket / sse_option / none，A 股批量分析用 sse_option。

关掉一个可选类别：macro_data / prediction_markets 这类海外补充源可以直接配 "none"（也认 off / disabled / skip），router 会立即返回 DATA_UNAVAILABLE 哨兵，一个请求也不发 —— 国内网络下这两个源连不上，留着只会每只股票、每个话题付一次连接超时。核心类别（行情/财报/新闻）配 none 会报错，因为决策依赖它们。

超时与主机跳过：海外端点用分段超时（连接 3s / 读取 10-20s）；某个主机连接失败后，本次运行会在 TRADINGAGENTS_HOST_BLOCK_COOLDOWN（默认 600 秒）内跳过它，不再重复等待。只有「连不上」才跳过，HTTP 4xx/5xx 与读取慢不算。

两个哨兵值的区别

哨兵值含义什么时候出现对智能体的影响
NO_DATA_AVAILABLE所有供应商都返回了"没有这个股票的数据"股票代码无效、已退市、不在覆盖范围智能体应报告"数据不可用"，不要编造
DATA_UNAVAILABLE供应商本身出了问题（网络错误、限流、未配置）API Key 没填、网络断了、被限流智能体应报告"数据源暂时不可用"，不要编造
为什么需要 fallback 链？

想象一下：AKShare 东方财富突然限流了（返回 429 错误），如果没有 fallback，整个分析就失败了。有了默认链 "akshare,yfinance"，系统会自动切到 Yahoo Finance 取数据，用户完全无感知。反过来说，分析一只美股（如 NVDA）时 AKShare 会先回答“没这个股票的数据”，链上下一个 yfinance 接着试 —— 这就是默认链把 akshare 放前面、美股分析仍然跑得通的原因。想只用一个源，把它单写即可（配 none / off / disabled / skip 则关闭该类别）。

2.3 理解 date_window.py —— 防止"偷看未来"的防护机制

这是量化交易中非常重要的概念：look-ahead bias（前视偏差）。简单说就是：你在 2026-09-01 做分析时，不应该看到 2026-09-02 才发布的数据。

Python date_window.py 核心函数
1def as_of(requested_date: str, trade_date: str) -> str: 2 """确保请求的日期不超过 trade_date（分析日期）""" 3 if requested_date > trade_date: 4 return trade_date # 截断到 trade_date 5 return requested_date 6 7def as_of_window(start: str, end: str, trade_date: str): 8 """确保整个日期窗口都不超过 trade_date""" 9 end = as_of(end, trade_date) # 结束日期不能超过 trade_date 10 return start, end
举例说明

假设 AI 分析师说"给我 NVDA 从 2026-08-01 到 2026-09-15 的股价"，但 trade_date 是 2026-09-01。

as_of_window("2026-08-01", "2026-09-15", "2026-09-01") 会把结束日期截断为 2026-09-01，实际请求变成 ("2026-08-01", "2026-09-01")。

这样就防止了 AI "偷看"分析日期之后的数据！

3.1 理解 AgentState —— 贯穿全程的"数据背包"

想象每个智能体都背着一个"背包"，里面装着分析过程中产生的所有信息。这个背包就是 AgentState。

Python state.py（简化版）
1class AgentState(MessagesState): 2 company_of_interest: str # "NVDA" — 分析哪只股票 3 trade_date: str # "2026-09-01" — 分析日期 4 instrument_context: str # "NVIDIA Corporation, US stock" — 公司身份 5 6 # === 分析师报告（并行写入，互不干扰）=== 7 market_report: str # 技术分析师的报告 8 sentiment_report: str # 情绪分析师的报告 9 news_report: str # 新闻分析师的报告 10 fundamentals_report: str # 基本面分析师的报告 11 12 # === 研究辩论状态 === 13 investment_debate_state: dict # 多空辩论记录 14 investment_plan: str # 研究经理的综合建议 15 16 # === 交易 & 风控 === 17 trader_investment_plan: str # 交易员的提案 18 risk_debate_state: dict # 风控三方辩论记录 19 20 # === 最终输出 === 21 final_trade_decision: str # 组合经理的最终决策文本 22 final_rating: str # "Buy" / "Sell" / ... / "REVIEW" 23 24 # === 记忆系统 === 25 past_context: str # 历史教训（注入给组合经理） 26 portfolio_context: str # 用户的持仓信息（可选）
关键理解

每个字段对应流程中的一个阶段。分析师只写自己的 report 字段（如 market_report），不会碰别人的字段，所以 4 个分析师可以同时工作（并行）。

数据流向是单向的：分析师 → 研究员 → 交易员 → 风控 → 组合经理。后面的角色可以看到前面所有人的输出。

3.2 理解 tools.py —— 分析师的"工具箱"

每个分析师都有一些"工具"可以调用，就像给 AI 配备了搜索引擎、数据库查询等能力。这些工具用 @tool 装饰器定义。

Python tools.py 示例（get_stock_data）
1@tool # 这个装饰器告诉 LangGraph：这是一个可调用的工具 2def get_stock_data( 3 symbol: Annotated[str, InjectedState("company_of_interest")], 4 start_date: Annotated[str, "Start date in yyyy-mm-dd format"], 5 end_date: Annotated[str, "End date in yyyy-mm-dd format"], 6 trade_date: Annotated[str, InjectedState("trade_date")] = "", 7) -> str: 8 """Retrieve stock price data (OHLCV) for the instrument.""" 9 start_date, end_date = as_of_window(start_date, end_date, trade_date) 10 return route_to_vendor("get_stock_data", symbol, start_date, end_date)
逐行解释

第 3 行：InjectedState("company_of_interest") 是一个"自动注入"机制。AI 调用这个工具时不需要传 symbol 参数，系统会自动从 AgentState 中取出 company_of_interest（即 "NVDA"）填进去。

第 6 行：同理，trade_date 也是自动注入的，AI 不需要传。

第 9 行：调用 as_of_window() 做日期截断，防止 look-ahead。

第 10 行：调用 route_to_vendor() 去获取数据。注意这里传的是字符串 "get_stock_data"，router 会根据这个名字找到对应的供应商实现。

3.3 理解 rating.py —— 5 级评级怎么从 AI 文本中提取

AI 输出的是自由文本（比如"我们建议买入 NVDA，因为..."），系统需要从中提取出标准化的评级。

Python rating.py 核心逻辑
1# 5 级评级（从最看多到最看空） 2RATINGS_5_TIER = ("Buy", "Overweight", "Hold", "Underweight", "Sell") 3 4def extract_rating(text: str) -> str | None: 5 # 用正则表达式在文本中找 "Rating: Buy" 这样的模式 6 # tolerant of markdown bold: "**Rating**: Buy" 7 # tolerant of fullwidth punctuation: "Rating：Buy" 8 ... 9 return "Buy" # 或 None（找不到时） 10 11def parse_rating(text: str, default="REVIEW") -> str: 12 rating = extract_rating(text) 13 return rating if rating else default # 找不到就返回 "REVIEW"
什么是 REVIEW？

当 AI 的输出中找不到任何可识别的评级时（比如 AI 写了一堆分析但没说 Buy 还是 Sell），系统返回 REVIEW。这不是一个可交易的信号，而是告诉用户"这个决策需要人工复查"。

重要：REVIEW 不等于 Hold！Hold 是一个明确的"持有"决策，REVIEW 是"无法解析"。

4.2 理解 setup.py —— 图是怎么建出来的

Python setup.py 核心逻辑（简化）
1def setup_graph(self, selected_analysts, memory_node=None): 2 # 创建一张空图 3 workflow = StateGraph(AgentState) 4 5 # 添加分析师节点（每个分析师是一个子图） 6 for spec in plan.specs: 7 workflow.add_node(spec.agent_node, _analyst_graph(...)) 8 9 # 添加其他节点 10 workflow.add_node("Bull Researcher", bull_researcher_node) 11 workflow.add_node("Bear Researcher", bear_researcher_node) 12 workflow.add_node("Research Manager", research_manager_node) 13 workflow.add_node("Trader", trader_node) 14 # ... 风控节点、组合经理节点 ... 15 16 # 添加边：START → 所有分析师（并行） 17 for node in first_steps: 18 workflow.add_edge(START, node) 19 20 # 分析师全部完成后 → Bull Researcher 21 workflow.add_edge(first_steps, "Bull Researcher") 22 23 # 条件边：Bull/Bear 之间循环辩论 24 workflow.add_conditional_edges("Bull Researcher", 25 should_continue_debate, DEBATE_PATH_MAP) 26 27 # 研究经理 → 交易员 → 风控 → 组合经理 → END 28 workflow.add_edge("Research Manager", "Trader") 29 workflow.add_edge("Trader", "Aggressive Analyst") 30 workflow.add_edge("Portfolio Manager", END)
关键概念解释

add_edge(A, B)：固定边，A 完成后一定去 B。

add_conditional_edges(A, func, path_map)：条件边，A 完成后调用 func 函数，根据返回值决定去哪个节点。

first_steps 列表传给 add_edge：表示这些节点并行启动，等全部完成后才触发下一个节点。

4.3 理解 conditional_logic.py —— 辩论怎么控制轮数

4.4 理解检查点机制 —— 崩溃了怎么恢复

检查点是什么？

想象你在玩一个很长的游戏，每过一关系统自动存档。如果游戏崩溃了，你可以从最近的存档继续，不用从头开始。

TradingAgents 的检查点就是这样：每完成一个节点（一个智能体的工作），就把当前状态保存到 SQLite 数据库。如果程序崩溃，下次运行会自动从最后一个成功的节点继续。

Bash 使用检查点
# CLI 方式：加 --checkpoint 参数 tradingagents --ticker NVDA --date 2026-09-01 --checkpoint # 如果崩溃了，再跑一次同样的命令，会自动从断点恢复 tradingagents --ticker NVDA --date 2026-09-01 --checkpoint # 成功后检查点自动清除。想手动清除： tradingagents --ticker NVDA --date 2026-09-01 --clear-checkpoints
签名机制

每个检查点都有一个"签名"，由分析师选择、辩论轮数、配置等计算得出。如果你改了配置（比如换了模型），签名就变了，旧检查点自动失效，从头开始。这样避免了用旧状态继续新配置导致的错误。

记忆系统 & 回测引擎

5.1 理解决策日志 —— 每次运行的"日记本"

记忆日志是什么？

每次运行结束后，系统会把决策写入一个 Markdown 文件（默认在 ~/.tradingagents/memory/trading_memory.md）。这个文件就像一个"日记本"，记录了每次分析的决策和后续的实际结果。

Markdown trading_memory.md 格式示例
[2026-09-01 | NVDA | Buy | +3.2% | +1.8% | 5d | resolved:2026-09-08] DECISION: Based on strong technical indicators and positive sentiment... REFLECTION: The Buy call was correct. NVDA gained 3.2% vs SPY's 1.4%... <!-- ENTRY_END --> [2026-09-08 | NVDA | Hold | pending] DECISION: Mixed signals from analysts suggest waiting...
标签行格式解读

[日期 | 股票 | 评级 | 实际回报 | Alpha回报 | 持有天数 | resolved:结算日期]

  • pending：还没到结算日，不知道结果
  • +3.2%：NVDA 在持有期内涨了 3.2%
  • +1.8%：扣除基准（SPY）后的超额回报（Alpha）
  • resolved:2026-09-08：这个结果是在 9 月 8 日知道的（用于 point-in-time 过滤）

Point-in-Time 语义

resolved:2026-09-08 这个字段很重要！当你在 2026-09-05 做分析时，系统只会加载 resolved <= 2026-09-05 的历史教训。这样就不会"偷看"未来的结果。

5.3 理解回测引擎 —— 批量评估决策质量

回测是什么？

单次分析不能说明系统好不好。回测就是让系统在多个股票 × 多个日期的网格上运行，然后统计整体表现。

比如：对 NVDA 和 AAPL，从 2026-06-01 到 2026-08-01，每隔 7 天分析一次，总共 4 个日期 × 2 只股票 = 8 个"单元格"。

Python 回测使用示例
from tradingagents.backtest import iter_grid, run_backtest, summarize # 生成日期网格：从 6月1日 到 8月1日，每 7 天一个日期 dates = iter_grid("2026-06-01", "2026-08-01", every_n_days=7) # 结果：["2026-06-01", "2026-06-08", "2026-06-15", ...] # 运行回测 result = run_backtest(["NVDA", "AAPL"], dates, config) # 查看汇总 print(summarize(result).render()) # 输出类似： # Resolved cells: 8 · pending: 0 # - Buy: n=3, called the direction 67%, mean alpha +2.1% vs the benchmark # - Hold: n=2, no direction claimed, mean alpha +0.3% vs the benchmark # - Sell: n=1, called the direction 100%, mean alpha +3.5% vs the benchmark
评分指标解释

hit_rate（命中率）：Buy/Overweight 的决策中，实际涨了的占比；Sell/Underweight 的决策中，实际跌了的占比。Hold 没有方向，所以不计算命中率。

mean_alpha（平均超额回报）：所有该评级决策的平均 alpha 回报。正数表示跑赢了基准。

重要：回测使用独立的记忆日志（在 results_dir/backtest/ 下），不会污染你的实盘记忆。

新增：内置选股器 — 五步筛选 + 交互确认，智能推荐 Top 3

新功能 什么是内置选股器？

内置选股器是 TradingAgents 的自动化选股工具，采用五步筛选漏斗：从 5000+ 只 A 股逐级筛选（基础过滤→资金面→消息面→技术面）找出几十只潜力股，交互确认后用多智能体深度分析推荐 Top 3。

🎯 核心特点：五步筛选 + 交互确认

  • 全市场覆盖：从 5000+ 只 A 股中智能筛选（非固定股票池）
  • 逐级筛选漏斗：基础过滤 → 资金面前 100 → 消息面利好板块 → 技术面几十只
  • 消息面优先：消息面筛选在技术指标计算之前，节省大量 API 调用时间
  • 交互确认：筛选完成后打印潜力股列表，由你决定是否深度分析（--yes 跳过提问，无人值守用）
  • 多智能体深度分析：复用 TradingAgents 的 12 个 LLM 智能体分析引擎
  • 综合评分排序：LLM 评级 40% + 技术面 30% + 资金面 20% + 动量 10%
  • 最终推荐输出：以表格清晰列出 Top 3 股票代码、名称、上涨潜力分数、综合评级
  • 交易点位建议：每只股票一行给出阻力位、支撑位、建议买入价、建议卖出价（近 20 个交易日高低点分位）
  • 盘前也可用：开盘前东财“今日”资金流为空时，资金面与板块热度自动改用最近一个已完成交易日的数据（近 5 日排行取候选池 + 并发精查），不会因筛出 0 只而中断
  • 自动报告生成：Markdown/HTML 格式的详细分析报告
